# 扩展 Scaling：把这套方法带到下一场事故

**本案是一个模板，不是孤本。** 本页回答"这套方法哪些部分可泛化、哪些是本案特有、扩展的成本在哪"。

## 可泛化层（方法内核）

1. **证据分级 + 追溯矩阵**：任何"多方叙述冲突的技术事件"都适用——披露点全集 → F0–F3 保真度 → 实现模块 → 检测配方。
2. **确定性即探测器**：任何依赖可复现性的系统（训练/仿真/构建），"同输入必同输出"是最便宜的入侵探测器。
3. **对账式检测**：以步骤起点可见状态 + 官方语义忠实重放，对照实际位移——适用于一切"日志与实际脱节"类破坏。
4. **工件完整性门**：哈希清单 + mtime/ctime 交叉——适用于一切共享环境。
5. **叙述对质矩阵**：各方主张 × 出处 × 可裁决材料清单——适用于一切罗生门。

## 本案特有层（不泛化）

T5/modify_t5 的具体机理、`.temp` 文件清单、barrier_vgpt 路径、MegaScale 机器粘性——这些是**本案的考古发现**，模板只引用其形态，不复制其内容。

## 扩展成本模型

| 阶段 | 成本 | 产出 |
|---|---|---|
| 事件直录 + 来源捕获 | 0.5 天 | 可哈希的一手材料库 |
| 披露点矩阵 + 保真度分级 | 1–2 天 | 1:1 追溯骨架 |
| 机制还原（F0/F1） | 视摘录量 | 对照报告 + 检测配方清单 |
| 现场复原 + 端到端 | 3–5 天 | 可走查装置 + 阳/阴双测 |

## 约束（迁移时的红线继承）

沙箱封闭、指人不指名、允许未知、F3 不冒充 F0——四条随模板走，一条不减。
