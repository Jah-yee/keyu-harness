## 基线固定规则

1. 记录历史 tag/commit，不把当前默认分支当作永久不变的版本。
2. 分开记录事件时间、项目公开时间和材料获取时间。
3. PyTorch 版本比较只有在运行环境版本有证据支持后，才能与特定任务关联。
4. LlamaGen 的 2024 年 6 月公开版本，不应自动代替 2024 年 3 月的内部 checkout。
5. Goku 的 2025 年论文与公开仓库，应与所述 2024 年事件时间线分开保存。
6. 无法取得的内部 commit、模型权重和训练日志，登记为 `U`，不通过虚构目录或推测补齐。

## T5 XL / XXL 的核验要点

公开配置中，FLAN-T5-XL 的 `d_model` 为 2048、`num_heads` 为 32；FLAN-T5-XXL 分别为 4096 和 64。它们可用于检查候选配置是否自洽，但不足以单独识别历史任务实际加载的权重。

至少需要核对模型 ID 与 revision、配置和 tokenizer 哈希、权重 shard 哈希、实际加载路径、缓存生成代码与 manifest，以及消费该工件的 job/run 标识。文件名正确或张量形状相符，都不能单独证明工件来源。

## 版本矩阵应如何扩展

每一行代表一个具体快照，而非一个项目的泛称：

| 字段 | 说明 |
|---|---|
| `project` | PyTorch / LlamaGen / Goku / T5 |
| `version_or_commit` | tag、commit SHA 或模型 revision |
| `published_at` | 公开发布日期 |
| `acquired_at` | 本研究取得材料的时间 |
| `tree_sha256` | 本地文件树 manifest 的哈希（若已生成） |
| `runtime_link` | 是否有证据连接到目标运行 |
| `status` | `PUBLIC_BASELINE`、`CANDIDATE`、`VERIFIED_RUNTIME` 或 `UNKNOWN` |

公开基线是比较的尺子，不是历史结论本身。
