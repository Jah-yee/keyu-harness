## 2026-10-28 决策记录

| # | 决策 | 被否决/被替代的方案 | 转向理由 |
|---|---|---|---|
| 1 | 研究定位 = "优化 loss 之外的一切" | ①"提升训练质量"（被否：质检科词汇，反讽不成立）②"信任优化系统"（被否：太抽象）③"现象层/实体层解耦"（被否：宏大定义） | 定位必须字面为真——十个特性无一触碰 loss 本身，这是实测事实而非修辞 |
| 2 | README = 案件卷宗体 | v2 诙谐版（俚语过多，被用户否："你把很多好的东西都删了"） | 保留原版"一本正经"内容是底线：改语气不删骨架 |
| 3 | 完整功能复刻（用户裁定） | RUN/STUB 分档方案（我方初始提案） | 沙箱内无特权边界可跨越——模拟世界的系统就是仓库目录；唯一保留约束=环境锁死 |
| 4 | 部署链从四阶段升为五层 | 保留四阶段模型 | LatePost"打窝"细节 + T5 载体机制无法被四阶段容纳 |

| 6 | 摘录不完整性作为独立主张 | 只作顺带观察 | wrapper 0 命中 vs 31 调用点=可实测证据（C28，DIRECTLY_SUPPORTED） |
| 7 | 法律线砍掉 | 追踪诉讼全程（用户裁定） | 叙述对质只保留"二审不公开导致部分说法不可核实"的边界说明 |
