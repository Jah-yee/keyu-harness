# 部署链假设 v2：田柯宇攻击 harness 的层级模型（2026-10-28）

**性质**：本文是被报道攻击系统的**层级假设模型**（F5/H），每层列出支持事实（标注来源与级别）、关键未知项和防御检测点。虚构与事实严格分离；不包含可运行攻击或规避代码。

## 模型总览

```text
A 散布放置层 ──► B 入口触发层 ──► C 安装/持久化层 ──► D 反取证层
     │                                                        │
     └────────────── E 命令通道层（独立循环，与 B 关系未知）◄────┘
```

与 v1 四阶段模型的差异：新增 A 散布层（LatePost"打窝"）与 D 反取证层；B 层从"init.py 单入口"扩展为三入口；C 层补全 Robust Training 机器粘性机制。

与主 README 十特性的对应：A 散布 ← 特性 08 的安装前态；B 入口 ← 特性 00/05/06/07；C 安装持久化 ← 特性 08/01/02/03/04 的落地；D 反取证 ← 特性 08 与日志删行；E 命令通道 ← 特性 05/06。

## A. 散布放置层

- **事实**：代码不止在个人目录（`.temp` 隐藏点目录，位于上百人有权限的共享服务器，2024-07-31 发现），还在**直属领导目录名下**与**公用数据文件夹的日志文件里**（F4-LP，"打窝一样，各处都放点"）；8-01 实时删除被存储操作记录恢复，恢复后**代码数量多于初见**。
- **目的假设（H）**：① 为 B 层"读目录执行"供料；② 清理后残存/重播；③ 混淆归属（文件在他人的目录名下）。
- **未知**：各处完整文件清单；日志内藏码的具体实现（代码藏在日志行内？日志文件格式被利用？）。
- **检测**：共享盘 ACL 审计（谁可写谁的目录）；日志文件完整性校验（日志中出现可执行内容模式告警）；跨目录同名/同哈希文件关联。

## B. 入口触发层（三入口并存）

1. **T5 载体**（F4-LP）：干预程序入口置于训练必加载的 T5 模型文件（"类似压缩包"）；改后组件读取不同目录下的攻击代码并执行；给机器加后门；每次实验启动随加载运行。
2. **init.py 启动触发**（F4-S01）：kill.py 把 wait 写入 init.py，随训练启动自动运行。
3. **checkpoint 加载路径**（F4-S01 nonan 卡片）：代码在 checkpoint 加载时执行（nan_to_num_ 语境），说明加载路径存在可执行上下文。

- **未知**：T5 载体的实现（修改的是权重文件本身、加载 hook、还是序列化机制）；三入口是否同属一套系统；与 E 层 barrier_vgpt 的关系。
- **关联公开风险佐证**：PyTorch v2.6.0 release notes 提及反序列化漏洞（issues 评论引用）；ws_v3 深度调研补充 §4.1 早已把"加载过程调用额外代码"列为独立取证问题——被本案材料证实为真实攻击面。
- **检测**：checkpoint/模型文件加载前哈希校验 vs 登记清单；safetensors 优先、拒绝不可信 pickle；加载路径代码审计（torch.load 周边无业务改动证明）。

## C. 安装/持久化层

- **事实链（现已闭环）**：
  1. 安装器脚本（a/e/r/re/re_a.py）用 sudo 替换机器上**已安装**的 torch 文件并还原 mtime/属主/权限（F4-S01 卡片 8）；
  2. 修改发生在**已分配且运行中**的机器上，不回传镜像仓库、不提交代码变更 → 绕过 review（F4-S01 issues #10 作者回复）；
  3. 系统使用 Robust Training（作者链接 arXiv:2402.15627 = **MegaScale 论文**）：训练中断后**机器不释放、任务不重拉镜像** → 被改源码跨任务持续生效（F4-S01 issues #10）。
- **历史印证（F4-LP）**：Chen 比对正常/异常机器 PyTorch 文件 mtime，差异在末尾两位纳秒级——时间戳篡改当年就是疑点起点。
- **未知**：安装器五脚本的分工；`py9_*`/`*39` 命名是否对应 python3.9 环境变体（H-FN-1）；raw_* 文件是否为原始备份。
- **检测（本仓库检测配方核心）**：`os.utime` 无法修改 ctime → mtime/ctime 不一致即可疑；job 启动时对 torch 关键模块哈希 vs 镜像清单核对；跨 rank 模块哈希一致性（同一 job 各 rank 应读同一容器层）。

## D. 反取证层

- **事实**（F4-LP）：多处修改**挤在同一行**避免行数增加（traceback 不显眼）；日志被自动程序**删除故障特定行**；**替换系统检查工具**；**隐藏运行中的攻击进程**（"确实有攻防"）。另有 mtime 还原（C 层）。
- **未知**：替换的是哪些检查工具（top/ps/lsof/自定义巡检？）；隐藏进程的手段（LD_PRELOAD？改 ps 源？proc 伪装？）——完全无公开细节。
- **检测**：日志 append-only + 独立采集身份；工具自身完整性校验（哈希在带外）；跨源时间线交叉（作业调度记录 vs 进程记录 vs 存储审计）。

## E. 命令通道层

- **事实**（F4-S01 卡片 5）：wait.py 轮询共享盘 `.../barrier_vgpt/<trial>/in.<id>`，目录内文本当 shell 命令执行并回写——无外网 C2，常规网络监控不可见；按 rank 取模只在个别进程运行。
- **未知**：barrier_vgpt 全路径；与 B 层 T5 载体是同一系统的两条腿，还是两代/两套实现（H）。
- **检测**：共享盘访问模式审计（读-执行-写回循环）；命令执行审计（训练账户的 shell 命令白名单）；`in.*`/`out.*` 文件模式告警。

## 层间依赖与单点观测

- A 依赖共享存储写权限（同组互写）——**共享存储是全链路的中心信任边界**（ws_v3 深度调研补充 §2.2 的判断被材料证实）。
- C 依赖机器粘性（Robust Training/MegaScale）——**容错设计的副作用**：为可用性保留的机器状态恰好为篡改提供了持久化。这是本案对 ML 系统安全设计最有普适价值的一课：**故障恢复路径必须与工件完整性校验绑定**（机器粘性可以保留，但重启任务时应核对关键模块哈希）。
- D 依赖日志与工具由训练环境自身控制——日志/工具的带外完整性是反"攻防"的根本。
