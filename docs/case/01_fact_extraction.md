### 2.2 机制卡片（8 项，摘录级）
1. adam/adamw 系：`maximize = group["maximize"] = True`（adamw2 按 rank 取模）。
2. clip_grad：`clip_coef_clamped = torch.ones_like(clip_coef).mul_(2)`，函数仍返回正常 norm；附带关闭 Flash/高效注意力、调高 matmul 精度、关 TF32。
3. 数字名文件 18/19/20/21/1839/1939/2039：以 2⁻¹⁸~2⁻²¹ 概率让进程"假装不在通信组"；种子=纳秒时间+对象地址。
4. r.py/re.py/data_dist：sampler 种子 `g.manual_seed(time.time_ns() % 10000000000)` 替换 `self.seed + self.epoch`。
5. wait.py：轮询共享盘 `.../barrier_vgpt/<trial>/in.<id>`，把文件内容当 shell 命令执行并回写；kill.py 把它写入 init.py 随训练启动触发。
6. kill.py：`pkill torchrun; sleep 10; pkill python`，按 TRIAL_ID/NODE_ID 触发。
7. nonan：checkpoint 加载时 `v.nan_to_num_(0, 0, 0)`。
8. a.py/e.py/re.py/re_a.py：sudo 替换已安装 torch 文件 + chown/chmod + `os.utime` 还原时间戳。

## 3. LatePost 事实清单（F4-LP）

### 3.1 技术机制（S01 未载）
1. **打窝散布**：代码在个人目录、**直属领导目录名下**、**公用数据文件夹的日志文件里**（"打窝一样，各处都放点"）；8-01 实时目睹删除，存储工程师调当日操作记录恢复，找到**更多**代码。
2. **T5 载体**：干预程序入口放在训练必加载的 T5 模型文件中（"类似压缩包"）；改后组件**读取不同目录下的攻击代码并执行**；给机器加后门；每次实验启动随加载运行（"蒲公英"）。
3. 发现装置：团队自建**确定性系统**，要求小数点后 16 位可复现；7-30 该系统失效于数据读取环节 → 定位 sampler。
4. mtime 取证：正常/异常机器 PyTorch 文件 mtime 差异在**末尾两位、纳秒级** → 怀疑时间戳篡改。
5. 反取证：多处修改**挤在同一行**不增行数；日志被自动程序**删除故障特定行**；**替换系统检查工具**、**隐藏运行中的攻击进程**（"确实有攻防"）。
6. 触发参数：预设概率决定是否攻击、目标会变；部分程序设 **GPU 数量门槛**；版本分析显示触发概率多次调整，"明显的连续性"。
7. 登录记录：7-30 异常机器除管理员外唯一登录者=田；此前 Infra 自动剔除机制失效过的机器上**也有**田的登录记录。
8. `.temp` 是**隐藏点目录**，位于**上百人有权限的共享服务器**。
