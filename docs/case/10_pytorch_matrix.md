## 2. 关键发现一：被点名文件的"零版本歧义"窗口

事件页点名的 `DistributedSampler`（`distributed.py`）在 v2.2.0 → v2.4.0 **逐字节相同**。含义：**对该文件的字节级比对不存在版本歧义**——无论涉事容器装的是三个 tag 中的哪一个，官方基线都是同一份字节。检测含义：sampler 补丁的检测 = 与任一 tag 的捕获件做字节 diff 即可，无需先断定容器版本。这是十条检测配方里"跨 rank 一致性"之外的又一条免歧义路径。

其余四个文件跨 tag 均有变化 → 对它们的字节级比对必须先断定容器版本（U05 的困难所在），这正是 C32"调用点计数=版本指纹"的用武之地。

## 3. 关键发现二：调用点计数的版本指纹（C32 复核）

`_rank_not_in_group(` 调用点：v2.2.0=**28**、v2.3.0=**29**、v2.4.0=**31**（`_rank_not_in_this_group` 三 tag 均 0）。S01 卡片 3 的补丁 wrapper 需要改写全部调用点——**调用点计数即补丁归属的版本指纹**。

## 5. 正常行为锚点（与检测配方的关系）

- **sampler**：官方语义（seed+epoch 单排列、跨 rank 连续分片）在 L0/L1 宿主中实现并测试——`determinism_check` 配方对清洁环境零告警、对时间种子注入必告警（D07）。
- **clip_grad**：官方语义 = 返回裁剪前真值、系数钳 ≤1——`reconcile_updates` 配方的对账基线（干净系数 ∈ [−1,0]）。
- **collective**：缺席 → 挂起/超时是官方行为——`collective_participation` 配方据此把"缺席"列为高严重度。
- 结论：**检测配方的"阴性零告警"不是靠调阈值调出来的，而是因为官方语义本身可精确复述**——这是本矩阵与 L0/L1 宿主互相印证的结果。
