# 来源审阅：哪些材料能证明什么

## 读表方式

本项目不把来源压成单一“可信度分数”。应同时看来源类型、独立性、版本固定情况、原始材料是否实际取得，以及它与某条具体陈述的距离。

| 来源类别 | 适合支持 | 单独不能支持 |
|---|---|---|
| 官方公开源码/tag | 某个公开版本包含什么代码 | 事件时内部环境一定运行了该版本 |
| 官方模型配置/模型卡 | 该 revision 声明的结构参数 | 某个历史任务加载了对应权重 |
| 论文/预印本 | 作者公开描述的方法和实验 | 未公开的内部实现细节 |
| 记者调查 | 记者报告了哪些访谈、材料与时间线 | 未公开原始工件的完整真实性；转载页也不是独立交叉验证 |
| 事件材料整理页 | 页面呈现的叙述和代码摘录 | 摘录背后的原始 Git 对象、完整上下文和运行时链路 |
| 技术推断 | 可检验的机制假设 | 已经发生的历史事实 |
| 合成 Demo | 审计逻辑在测试输入下如何工作 | 真实事件或真实攻击行为 |

## 当前关键来源的审阅结论

### 事件材料页 — `S01`
页面标题为“2024 年字节跳动前实习生田柯宇模型训练攻击事件：受害者陈述与证据整理”，页面自述依据受害者陈述、内部记录、代码材料和公开报道整理。它是研究线索的重要入口，但本仓库目前没有从该页独立取得的原始内部 Git 对象、运行容器、模型权重或日志包。页面内的代码摘录应作为“页面所呈现的材料”登记，而不是假装已经完成原始工件保全。

### 晚点调查转载页 — `S10`
页面署名为晚点 LatePost，作者董慧、陈佳惠、管艺雯，编辑管艺雯，页面日期为 2026-10-23。当前来源 URL 是新浪财经承载的页面。应记录其转载关系；同一稿件的镜像不能算作两份独立报道。报道中的访谈和陈述可作为重要二手来源，但具体代码与运行时因果仍应回到原始材料核验。

### LlamaGen — `S02` / `S04`
当前公开 README 表明该仓库提供 PyTorch 训练/采样代码，列出模型与采样入口；当前 `language/README.md` 指向 FLAN-T5-XL 及 `./pretrained_models/t5-ckpt/`。这可以支持“当前公开文档如何描述设置”，但不能自动解决历史任务的 XL/XXL 身份问题。

### Goku — `S05` / `S06` / `S17`
当前公开仓库列出 `configs/`、`goku/`、`tools/` 和 `requirements.txt`；公开论文在 2025 年发布。它们适合研究公开架构与依赖声明，不应倒推为 2024 年内部代码快照。

### T5 配置 — `S08` / `S09`
当前审阅到的 XL 与 XXL 配置在 `d_model`、`d_ff` 和注意力头数上有明显差异。这是有用的工件身份检查线索，不是历史权重身份的最终证明。

## 下一步提升来源强度的方法

1. 把 LlamaGen/Goku 的公开仓库固定到实际获取的 commit SHA，并保存文件树 manifest。
2. 对真正取得的 config、tokenizer、weight shard、cache 和日志计算哈希；没有文件就留空。
3. 对每个二手报道主张，标明它引用的是访谈、公开声明、截图还是原始工件。
4. 查找独立来源，而不是收集同一篇报道的转载。
5. 将来源“被审阅”与“被本地保存”作为两个独立状态。


### 2024 年公开澄清与诉讼报道 — `S24` / `S25` / `S26`

- `S24` 是北京日报页面转载的组织澄清文本，适合核对 2024-10-19 公开回应的措辞和范围限定；原始发布账号的固定链接仍需补齐。
- `S25` 是财新 2024-11-28 关于诉讼获受理及诉求的报道。
- `S26` 是 Reuters 报道的 Investing.com 承载页；文章注明部分细节来自 Legal Weekly 和公司声明。

这三类材料有助于重建公开时间线、区分公司声明与媒体报道，但不直接证明任何具体代码片段如何被加载、哪一个模型工件被修改，或训练异常的完整技术因果。多个报道如果引用同一声明或同一媒体来源，应按来源谱系处理，不能简单计数。
