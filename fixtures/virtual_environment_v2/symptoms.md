# 四个症状展品（全部 SIMULATED；数值为教学填充，不构成对被报道机制的参数估计）

## 展品 A：跨 rank 采样排列不一致（sampler 时间种子）

`det-harness` 在第 2 步记录的各 rank 前 8 个样本索引（预期：所有 rank 一致）：

```text
rank00: [10442, 771,  3900, 8802, 3321, 9190, 6408, 1222]
rank01: [10442, 771,  3900, 8802, 3321, 9190, 6408, 1222]
rank02: [9213,  4406, 10987, 2088, 5511, 7742, 341,  6550]   ← 分叉
rank03: [10442, 771,  3900, 8802, 3321, 9190, 6408, 1222]
rank31: [3310,  9084, 7755,  1299, 4920, 221,  8871, 5480]   ← 分叉
```

诊断路径（教学中应引导的思考）：先怀疑自己的 dataloader → 隔离单机复现 → 复现失败（时间种子下每次都不同）→ 只有"实验应可复现"这条物理学性质是可靠的检查点。**锚点**：S01 卡片 4 + LP 确定性系统叙述。

## 展品 B：日志范数恒定而 loss 发散（clip_grad 真范数错位）

```text
step   logged_grad_norm   actual_pre_clip_norm   loss
5100   0.87               0.87                   2.01
5101   0.91               0.91                   2.00
5102   0.85               0.85                   1.99
5103   0.89               1.78                   2.44   ← actual 为日志值 2 倍（教学设定）
5104   0.90               1.80                   2.87
5105   0.88               1.76                   3.31
```

诊断陷阱：日志说梯度正常、优化器参数正常 → 你会去查学习率和数据。**检查点**：独立重算一次梯度范数并与日志对账（在真实环境中=与"日志里的 norm"是同一来源还是两路采集）。**锚点**：S01 卡片 2（函数仍返回真范数→日志失真）。

## 展品 C：日志行缺失（自动删行）

同一作业两路采集的日志对比（路 1：进程本地 stdout；路 2：`det-harness` 独立写盘）：

```text
路1（可被环境内进程触碰）:          路2（独立身份写盘，对照用）:
...                                 ...
step 5100 loss=2.01                 step 5100 loss=2.01
step 5101 loss=2.00                 step 5101 loss=2.00
step 5102 loss=1.99                 step 5102 loss=1.99
                                    step 5103 loss=2.44   ← 路1 缺失
step 5104 loss=2.87                 step 5104 loss=2.87
                                    step 5103 grad_spike=1.78  ← 只有独立路有
...                                 ...
```

诊断要点：看到"日志突然很干净"要起疑——**缺失本身就是信号**。**锚点**：LP"日志被自动程序删除故障特定行"。

## 展品 D：mtime 与 ctime 不一致（utime 反取证残留）

对同一路径两个来源的时间查询（教学演示；`os.utime` 可改 mtime/atime，改不了 ctime）：

```text
$ ls -l --time=mtime torch/optim/adamw.py
-rw-r--r-- 1 root root 14817 Jun  2  2024 torch/optim/adamw.py     ← 与镜像内一致，"没动过"

$ ls -l --time=ctime torch/optim/adamw.py
-rw-r--r-- 1 root root 14817 Jul 14 09:47 torch/optim/adamw.py     ← inode 变更时间暴露

$ stat -c '%y %z' torch/optim/adamw.py
2024-06-02 08:00:00.000000000   2024-07-14 09:47:33.112458901
       mtime（被还原）                ctime（还原不了）
```

诊断要点：批量核对"mtime 正常但 ctime 异常"的文件列表；再对节点间/镜像间做逐文件哈希。**锚点**：S01 卡片 8（utime 还原）+ LP 纳秒级 mtime 差异（当年真实的疑点起点）+ S01a issues #10（机器粘性下修改跨任务存活）。
