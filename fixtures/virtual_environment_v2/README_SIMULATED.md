# SIMULATED / FICTIONAL — 虚拟实验装置 v2（走查指南）

> **本目录全部内容为虚构教学样本。** 组织名、人名（engineer-XXX 等占位符）、路径、job、日志、指标都是为演示而造的，不对应任何真实内部系统。装置的每个展品只在**一个维度**上忠于公开材料：症状的形态与被报道机制一致；其余一切（具体数值、时间、路径）均为教学填充。

## 这个装置是什么

一个"可走查"的假设性内部环境切片：想象你是一位 2024 年夏天加入该团队的工程师，这个装置让你在**不含任何真实攻击代码**的前提下，走一遍"攻击 harness 存在时训练环境是什么手感"，并亲手运行检测配方把它找出来。

它是一座考古装置，不是一个复刻品：展品 = 被报道机制的**症状层**，不是实现层。

## 走查路线（约 15 分钟）

1. **`org_and_env.md`** — 认识环境：虚构组织表、集群规格、共享存储布局。注意每个字段旁的 `[REPORTED-BASIS: …]` 锚点。
2. **`job_timeline.tsv`** — 一次虚构作业的生命线：20 个事件里，哪些有公开材料锚点、哪些是教学填充，看 `basis` 列。
3. **`symptoms.md`** — 四个症状展品，每个对应当年团队真实遭遇的一类现象：
   - 展品 A：跨 rank 采样排列不一致（sampler 时间种子）
   - 展品 B：日志范数恒定而 loss 发散（clip_grad 真范数错位）
   - 展品 C：日志行缺失（自动删行）
   - 展品 D：mtime 与 ctime 不一致（utime 反取证残留）
4. 对每个展品问一句：**"如果是你，先查哪里？"** 然后对照 `docs/case/03_deployment_chain.md` 的检测点，看你会不会被 D 层带走。

## 铁律

- 不向本目录添加任何可执行攻击/规避逻辑；展品只呈现"被观测到的后果"。
