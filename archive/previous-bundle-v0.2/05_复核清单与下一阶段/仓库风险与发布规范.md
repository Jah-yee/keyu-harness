# 仓库风险与发布规范

- 不把模拟路径命名成可误认为真实内部系统的路径；保留 `SIMULATED`/`FICTIONAL` 标记。
- 不编造主管、真实员工目录、内部 GitLab 项目名或私有链接。
- 不将某个人的主观指控写成事实；在证据账本中使用“来源称”“尚未独立验证”等限定。
- 不将公开仓库当前内容作为事故时的原始源码。
- 不将模型 ID 或范数相同当作权重相同；使用文件哈希、revision、config、tokenizer 和加载路径建立证据链。
- 不把公开 README、模型卡或项目名称与未经证实的“内部训练模型”关联。
- 对任何演示用“错误模型登记”使用虚构 artifact ID；不要把它伪装成真实模型作者的欺诈行为。
- 在 GitHub 发布前复核各上游项目许可证、引用格式、商标与归属声明。
