# 项目章程

## 研究问题

THAL 的目标不是猜出一个“看起来像真的”攻击程序，而是把公开证据、历史版本、运行时工件和教学模拟分开管理。它希望回答：

1. Goku 与 LlamaGen 的公开实现分别包含哪些模块和工件？
2. 在 2024 年各时间点，哪些版本已经公开，哪些只能作为后续研究参照？
3. T5 权重、tokenizer、文本特征缓存、主模型 checkpoint 如何分别建立 provenance？
4. 一个训练系统的控制面、数据面、执行面和证据面怎样关联？
5. 哪些观测能支持故障假设，哪些还不足以支持因果结论？

## 范围

主对象：Goku、LlamaGen、T5 工件谱系。PyTorch 作为执行与依赖层的基线参照。VAR/PixArt 不纳入当前主线。

## 非目标

- 不宣称重建了当事人真实内部目录、账户、直属上级或协作网络。
- 不实现真实仓库篡改、隐蔽执行、权重污染、后门植入、进程终止或绕过审计。
- 不将未经证实的个人行为指控写成事实。
- 不将当前公开仓库的 `main` 当作 2024 年历史版本。

## 方法学

1. 来源批判：每项主张标注来源、独立性和限制。
2. 软件供应链分析：commit → build → container → runtime → model artifact → job。
3. 数字取证：只读采集、SHA-256、文件清单、时间线和保管记录。
4. 可复现实验：用合成工件验证检测逻辑。
5. 故障分析：从异常指标回溯到数据、模型、执行、调度和记录层，保留替代解释。
