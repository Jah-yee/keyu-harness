# 03｜T5 型号差异：XL 与 XXL

## 目前观察到的差异

| 来源 | 明确写法 | 来源类型 | 可以支持什么 | 不能支持什么 |
|---|---|---|---|---|
| 事件整理页 | `flan-t5-xxl` | E4：一方事件叙述与代码材料摘录 | 该页面把涉事工件称为 XXL | 不能替代实际文件/历史 commit |
| LlamaGen 当前 `language/README.md` | `flan-t5-xl` | E1：公开仓库文件 | 当前 README 指向 XL | 不能证明 2024 年 3 月当时 README/环境相同 |
| Hugging Face `google/flan-t5-xxl` | 模型 ID 为 XXL，模型卡/文件列表可查 | E1：公开模型卡 | 可以确定该公开模型的身份与发布文件 | 不能证明事故中的文件就是它 |

## 可能解释（全部待核）

- 2024 年的历史 commit 与当前 README 不同；
- 内部环境使用自定义路径或另一份模型副本；
- “XL/XXL”在二手叙述中被误记；
- T5 权重、tokenizer 和缓存特征的版本被混合描述。

没有历史 commit 与原始工件前，不选择任何一种解释。

## 最小取证包

对每个候选模型，记录：
- 模型 ID 与 revision/commit；
- `config.json` 与 tokenizer 文件的 SHA-256；
- 权重格式、分片列表、文件大小和 SHA-256；
- 训练作业实际加载的路径；
- 生成缓存的预处理代码 commit、输入数据版本与缓存哈希；
- 运行时日志中的模型路径/版本（如有）；
- 文件的取得方式、时间与保全记录。

## 不能把统计相似当成内容相同

范数相同、均值接近、模型能够加载，都不足以证明两个 checkpoint 一致。整文件哈希和逐 tensor 哈希可以证明字节层面的相同性/差异，但不能单独证明差异的成因或训练影响。
